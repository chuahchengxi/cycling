# Rest Stops Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Leisure and Moderate routes show water and toilet stops; rides over 20 km get rest stops spaced by the rider's level and chosen by facility quality, with a warning before a water gap, in route detail, on the map and as a pass-by message during the ride.

**Architecture:**
- A pure `RestStops` enum (Features/Kit) finds amenities along the line with the existing Discovery corridor filter, clusters ones at the same spot into one stop, scores each stop and picks one per spacing window.
- The rider's level comes from the profile until 5 finished rides exist, then from those rides.
- Stops are saved on the `Route` next to the picks (`restStopData`), computed in the same two places the picks are, and copied into `RideRecorder`, which raises them with the same approach-and-pass logic as sights.

**Tech Stack:** Swift / SwiftUI / SwiftData, iOS 18+, assert-based `selfCheck()`s run at launch in DEBUG (`zsh .superpowers/sdd/fix/run.sh` prints LAUNCH CLEAN).

**Spec:** `docs/superpowers/specs/2026-11-20-kit-personalised-places-design.md`, section 3 (and "When things are decided").

## Global Constraints

- Leisure and Moderate routes of any length get rest stops; Fast gets none.
- Under 20 km: show the water and toilet stops along the route, no spacing windows.
- Spacing by level: Beginner 5–7 km, Regular 10–15 km, Strong 15–20 km. Starts from the onboarding choice; after 5 finished rides, re-estimated from recorded distance/speed.
- Choice by quality within each window: water > toilet > shade/shelter > food > bike parking; repair station is a bonus. Never closed or no-cycling.
- Gap warning copy: "No water for <n> km — fill up here" at the stop before the gap.
- Shown in route detail rows, as map pins, and as a Kit `Rest stop` pass-by message reusing `RideRecorder.checkSights`' approach-and-pass mechanism.
- Fully offline; MainActor by default, heavy pure work `nonisolated` and run in `Task.detached`. Rider-facing text spells out "hawker centre" and "park connector".
- Old saved routes without the new field decode with no rest stops.

## Review Focus

1. **A window with no amenity at all** (a 9 km stretch of coast with nothing): the next stop is the first one after the window, never a skipped stop or a crash. (Task 1 test.)
2. **The end of the route:** no rest stop is placed within the last `spacing.lowerBound / 2` of the ride; the finish is the rest. (Task 1 test.)
3. **Many amenities at one spot** (a hawker centre with toilets, taps and parking): one stop with all facilities, not four rows. (Task 1 test.)
4. **A closed or no-cycling toilet** is never a stop even when it's the only one in a window. (Task 1 test, via Discovery's existing filters.)
5. **Rides imported with zero moving seconds** don't divide by zero in the level estimate. (Task 2 test.)

### Task 1: Choose rest stops along a line

**Files:**
- Modify: `cyclingskibidi/Features/Routes/Discovery.swift` (`sights(along:)` gains `categories: Set<String> = leisureCategories`)
- Create: `cyclingskibidi/Features/Kit/RestStops.swift`
- Modify: `cyclingskibidi/App/cyclingskibidiApp.swift` (call `RestStops.selfCheck()`)

**Interfaces:**
- Produces:
  - `nonisolated struct RestStop: Codable, Identifiable, Sendable, Equatable { var id = UUID(); var name: String; var lat, lon: Double; var offsetAlong: Double; var amenities: [String]; var warning: String? }` — `amenities` are places.json categories, sorted by `RestStops.rank`; `coordinate` computed.
  - `nonisolated enum RestStops`:
    - `static let amenityCategories: Set<String> = ["drinkingWater", "toilets", "shelter", "hawker", "cafe", "bikeParking", "repair"]`
    - `static func spacing(_ level: RiderLevel) -> ClosedRange<Double>` (metres: 5000...7000, 10000...15000, 15000...20000)
    - `static func cluster(_ amenities: [Sight], radius: Double = 60) -> [RestStop]` — amenities in route order; one joins the current stop when within `radius` of its first member. Name: the hawker/cafe/shelter name if one has a real name, else "<top amenity label> · km <n.n>" using `Discovery.icon(for:).label`.
    - `static func quality(_ s: RestStop) -> Double` — drinkingWater 16, toilets 8, shelter 4, hawker or cafe 2 (once), bikeParking 1, repair 0.5; summed.
    - `static func choose(_ stops: [RestStop], length: Double, level: RiderLevel) -> [RestStop]`
    - `static func along(_ polyline: [Coord], mode: RideMode, level: RiderLevel, start: Date = .now, places: [Sight] = Discovery.places, facts: [String: PlaceFacts] = Discovery.facts, closed: [NoGoCircle]? = nil, walk: [NoGoCircle]? = nil) -> [RestStop]` — `[]` for `.fast`; else `Discovery.sights(along:mode:start:in:facts:closed:walk:limit: nil, categories: amenityCategories)` → `cluster` → `choose`.

`choose` rules (the algorithm the tests pin):
- `length < 20_000`: every stop that has `drinkingWater` or `toilets`, no warnings.
- Otherwise, with `w = spacing(level)` and `last = 0`: while `length - last > w.upperBound`: candidates are stops with `last + w.lowerBound <= offsetAlong <= last + w.upperBound`; take the highest `quality` (tie → earlier). If none, take the first stop after `last + w.upperBound`; if none at all, stop. Then `last = chosen.offsetAlong`. Never choose a stop with `offsetAlong > length - w.lowerBound / 2`.
- Warnings: for each chosen stop that has water, if the next chosen stop lacks water, measure from it to the next *chosen* stop with water (or `length`); if that is ≥ 5000 m, set `warning = "No water for \(Int((gap/1000).rounded())) km — fill up here"`.

## Decisions this plan makes

- **A stop is a cluster of amenities within 60 m**, so a hawker centre's toilets, taps and parking are one place to rest.
- **Hawker centres and cafés count as food at a stop** even though they're also leisure picks; a stop and a pick at the same place both show.
- **Warnings measure to the next chosen stop with water**, since that's where Kit will next send the rider.
- **The rest stop message comes 300 m early**, unlike sights, which show as they're passed: you need time to slow and pull in.
